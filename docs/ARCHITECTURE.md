# 安卓实现方案

开发决策日期：2026-11-05。用户已确认目标设备为 vivo X200s 与 iQOO Neo7 SE，接受录像自动分段；系统版本待真机记录。沿用 API 26 最低版本，compile SDK 36.1、target SDK 36。

## 连接与配对

拍摄端开启临时 TLS ServerSocket，二维码包含协议版本、私网 IPv4 地址列表、端口、随机 256 位会话令牌和证书 SHA-256。观看端只接受受支持的 Farview 二维码和私网 IPv4，不通过二维码访问互联网地址。系统不保存二维码、对端地址或令牌。

拍摄端监听 IPv4 通配地址。二维码地址优先选择 Wi-Fi / 以太网接口，排除系统标记为蜂窝网络、VPN 的接口及常见蜂窝 / 隧道接口；热点提供方未被 ConnectivityManager 注册的 AP 接口仍可使用。

观看端枚举已连接的局域网，不要求 INTERNET 或 VALIDATED 能力。优先用同网段 Wi-Fi / 以太网 Network 绑定单个套接字，再建立 TCP 和证书固定的 TLS；热点提供方可绑定 AP 本地源地址，并保留其他局域网与系统直连后备路径。应用不切换整个进程的默认网络。每轮重试重新读取网络信息，结束会话时关闭尚在连接或握手的套接字。

TLS 1.2 / 1.3 以二维码证书指纹校验拍摄端，令牌在 TLS 建立后验证。密钥存放 AndroidKeyStore；证书只是本地身份，不依赖公共 CA。服务端只接受一个观看连接。结束或刷新会话后令牌更换，旧码无法重新加入。系统备份关闭，避免本地身份和录像缓存进入云备份。

连接不依赖广播发现、外网信令、STUN 或 TURN。两种热点提供方向都需要真机测试：厂商热点的设备隔离、网络路由或 VPN 会影响连通性。地址变化时可返回重新扫码；当前重连只尝试本次二维码中的地址。

连接页区分建立 TCP、TLS 握手和等待配对确认，并显示超时、证书不匹配、权限拒绝等反馈。两端的配对 / 连接页及会话中的关于页可复制连接诊断，内容包括系统版本、接口地址、尝试路径和最近 10 条连接事件 / 异常原因链，不包含会话令牌、二维码正文或证书指纹。诊断只随本次会话保留在内存中，不自动上传。

## 视频与控制

Camera2 → SurfaceTexture / EGL 时间戳归一化 → MediaCodec H.264 编码 → TLS 二进制帧 → MediaCodec 解码 / MediaMuxer 录像。EGL 桥接使用单调时钟，避免旧版相机 HAL 的帧时间戳跳变影响编码。

编码输出在独立线程读取，避免 EGL 等待编码器输入缓冲时阻塞输出回调及相机控制。流重建先使旧代次失效，再释放旧编码器，迟到的回调不会污染新视频流。

视频默认 30 fps 目标帧率，720p 约 2.8 Mbps、1080p 约 5 Mbps；实际帧率受曝光、硬件和传输影响。发送队列有限，拥塞时丢弃排队画面并等待新关键帧，防止不断累积延迟；控制消息优先。TCP 在丢包时仍存在队头阻塞，延迟、码率和自动画质阈值需按真机结果调整。

自动模式在约 20 秒稳定余量后尝试升级；RTT、发送阻塞和队列拥塞影响判断，切换设冷却时间。它不是固定性能承诺，也不在 UI 显示一个未经校准的延迟数字。手动画质不会自动改变分辨率。

能力来自系统公开的后置相机 ID；不伪造 0.5×、3× 或某个厂商私有镜头。连续变焦使用 zoom ratio 或传感器裁剪范围。设备未公开的副摄不会被列出。普通自动曝光、白平衡和连续视频对焦为基础能力，不保证厂商相机的美颜、夜景和 HDR 效果，也不展示无法执行的效果开关。

控制指令携带请求 ID，返回拍摄端状态和执行结果。相机操作等待实际捕获回调确认，超时不会假装执行成功。画面方向以传感器固定方向为基础；观看端每次手动旋转 90°，不跟随拍摄手机姿态，不改变录像内容。

## 生命周期

拍摄端使用 camera 类型前台服务；观看端连接使用 connectedDevice 类型前台服务。服务保持 CPU 唤醒与持续状态通知，必须由前台页面启动，进程退出后不从后台偷偷重启相机。

非主动断线保留本次会话并重连；断线立即停止录像，尽力保存当前有效片段。主动结束先结束录像和保存任务，再释放网络、相机和通知。没有近期新视频帧时，观看端遮罩旧画面，不把静止画面当作实时直播。

系统电源键熄屏可继续运行前台相机服务，但 vivo / iQOO 的电池策略、相机隐私设置和系统版本可能限制它。App 不申请设备管理员权限，不会用普通黑色页面声称屏幕硬件已关闭。

## 录像

录像直接封装接收到的 H.264，不采集音频、不额外编码。每段从完整关键帧开始，分辨率或镜头格式发生变化时结束当前 MP4 并建立下一段；连接恢复不触发续录。

文件先写应用私有目录；正常封装完成后复制到相册，API 29+ 使用 MediaStore pending 状态，API 26–28 通过运行时存储权限及系统扫描入库。失败时保留私有文件，关于页提供重试。相册复制在独立队列进行，避免阻塞实时接收。

异常退出可能使当前 MP4 的索引来不及完成。重启后可以检查保留文件，对可读取的片段重试保存；无法读取的临时片段保留但不声称恢复成功。尚不提供损坏 MP4 的重建工具。

## 更新

仅手动读取 GitHub 最新正式 Release，确定同一 release 标签下的 update.json 和 farview.apk，避免先后读取 latest 时错配。HTTPS 跳转限制为 GitHub 资产域名，并限制超时、内容大小和重定向次数。

下载安装前校验摘要、包名、版本、最低系统和安装证书与当前应用一致。拍摄、观看、录像或保存任务尚未结束时不调起安装器。未知来源授权与最终安装由系统和用户完成；不预先报告安装成功。
